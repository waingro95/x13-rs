Seasonal adjustment with X-11.

X-11 estimates the seasonal pattern with a sequence of moving averages. You can
run it directly on the series, or after a regARIMA model has extended the
series with forecasts and removed calendar effects, outliers and gaps. The
[regARIMA guide](crate::guide::regarima) covers the model side.

| Request | Constructor |
| --- | --- |
| Direct X-11, on the series as given | [`Spec::x11`] |
| regARIMA preprocessing, then X-11 | [`Spec::x11_regarima`] |

Both take an [`x11::Options`], which holds every X-11 setting, the decomposition
mode included.

Every X-11 request needs at least three years of observations
([`Error::TooShort`]). The series, with any forecasts and
backcasts, must fit in 85 calendar years and 1020 periods
([`Error::SeriesTooLong`]). A fixed Henderson trend filter must not have more
terms than the values X-11 filters, the observations plus any forecasts and
backcasts ([`Error::HendersonLongerThanSeries`]).

# Adjust with direct X-11

Direct X-11 filters the series as given. It fits no model and adds no
forecasts, so the filters at each end of the series are asymmetric. Every value
must be present: a NaN returns [`Error::MissingValue`]. Use regARIMA
preprocessing when the series has gaps.

```rust
# fn synthetic(years: usize) -> Vec<f64> {
#     let mut season = [0.90, 0.94, 1.00, 1.03, 1.06, 1.09, 1.08, 1.05, 1.01, 0.98, 0.93, 0.93];
#     let mut state: u32 = 1;
#     let mut noise = move || {
#         state = state.wrapping_mul(1_103_515_245).wrapping_add(12_345);
#         f64::from(state >> 8) / f64::from(1u32 << 24) - 0.5
#     };
#     let mut level = 100.0;
#     (0..12 * years)
#         .map(|i| {
#             level += 0.4 + noise();
#             season[i % 12] += 0.01 * noise();
#             season[i % 12] * level * (1.0 + 0.02 * noise())
#         })
#         .collect()
# }
use x13::{Period, Series, Spec, diagnostics, x11};

let values = synthetic(8); // eight years of monthly data
let start = Period::monthly(2012, 1)?;
let adjustment = x13::adjust(Series::new(start, &values), &Spec::x11(x11::Options::new()))?;

let seasonal = adjustment.seasonal().expect("X-11 returns every component");
let adjusted = adjustment.seasonally_adjusted();
assert_eq!(adjusted.len(), values.len());

// Multiplicative: the seasonal component is a factor around one.
for ((value, factor), adjusted) in values.iter().zip(seasonal.values()).zip(adjusted.values()) {
    assert!((adjusted * factor - value).abs() < 1e-9 * value);
}

let x11 = adjustment.diagnostics().x11().expect("an X-11 adjustment");
assert_eq!(x11.mode(), x11::Mode::Multiplicative);
assert_eq!(
    x11.seasonality().combined().ok(),
    Some(&diagnostics::CombinedSeasonality::Present)
);
# Ok::<(), Box<dyn std::error::Error>>(())
```

# Choose a decomposition mode

[`x11::Mode`] sets how the components combine:

- **Multiplicative**: original = trend × seasonal × irregular. Every value
  must be positive ([`Error::NonPositiveValue`]).
- **Additive**: original = trend + seasonal + irregular. Any finite values.
- **Log-additive**: additive on the logarithm of the series, with the
  components returned as factors. Every value must be positive.
- **Pseudo-additive**: for series with values at or near zero in some
  seasons. Zeros are allowed, negative values are not
  ([`Error::NegativeValue`]). The adjusted series is
  original − trend × (seasonal − 1), and the irregular is adjusted ÷ trend.

[`x11::Options::with_mode`] sets the mode. With none set, [`Spec::x11`] runs
multiplicative X-11, and [`Spec::x11_regarima`] takes the mode from the
model's transformation: identity gives additive and log gives multiplicative.
With regARIMA preprocessing, leave the mode unset unless you need log-additive
or pseudo-additive X-11. Automatic transformation selection needs it unset,
and returns [`Error::InvalidSpec`] otherwise.

When [`Spec::x11_regarima`] has a mode set, regression effects
(calendar effects, outliers, supplied regressors and the regressors that stand
in for missing values) must be on the scale X-11 uses, so they need identity
with additive X-11, or log with any other mode. Other pairs return
[`Error::InvalidSpec`]. A model with no regression effects, or with only a
constant, accepts any mode. Pseudo-additive X-11 takes none of these effects
except the regressors for missing values, and returns [`Error::InvalidSpec`]
for the others.

When an X-13ARIMA-SEATS spec file names no transformation, the program runs
multiplicative X-11 on the untransformed series. The equivalent request sets
[`x11::Mode::Multiplicative`] and keeps the identity transformation, so it
takes no regression effects:

```rust
# fn synthetic(years: usize) -> Vec<f64> {
#     let mut season = [0.90, 0.94, 1.00, 1.03, 1.06, 1.09, 1.08, 1.05, 1.01, 0.98, 0.93, 0.93];
#     let mut state: u32 = 1;
#     let mut noise = move || {
#         state = state.wrapping_mul(1_103_515_245).wrapping_add(12_345);
#         f64::from(state >> 8) / f64::from(1u32 << 24) - 0.5
#     };
#     let mut level = 100.0;
#     (0..12 * years)
#         .map(|i| {
#             level += 0.4 + noise();
#             season[i % 12] += 0.01 * noise();
#             season[i % 12] * level * (1.0 + 0.02 * noise())
#         })
#         .collect()
# }
use x13::{ArimaModel, Error, ErrorKind, Period, RegArimaSpec, Series, Spec, Transform, x11};

let airline = ArimaModel::airline();
let start = Period::monthly(2012, 1)?;
let mut values = synthetic(8);

let multiplicative = x11::Options::new().with_mode(x11::Mode::Multiplicative);
let untransformed = Spec::x11_regarima(RegArimaSpec::new(airline), multiplicative);
assert!(x13::adjust(Series::new(start, &values), &untransformed).is_ok());

// A gap adds a missing-value regressor, an effect in series units, which
// multiplicative X-11 cannot remove.
values[30] = f64::NAN;
let error = x13::adjust(Series::new(start, &values), &untransformed).unwrap_err();
assert!(matches!(error, Error::InvalidSpec(_)));
assert_eq!(error.kind(), ErrorKind::InvalidSpec);

// Log preprocessing puts the effect on the multiplicative scale.
let logged = RegArimaSpec::new(airline).with_transform(Transform::Log);
let spec = Spec::x11_regarima(logged, multiplicative);
let adjustment = x13::adjust(Series::new(start, &values), &spec)?;
assert!(adjustment.seasonally_adjusted().values()[30].is_finite());
# Ok::<(), Box<dyn std::error::Error>>(())
```

# Set X-11 options

[`x11::Options::new`] starts from the X-13ARIMA-SEATS defaults:

- seasonal filters chosen from the moving seasonality ratio (MSR);
- a Henderson trend filter whose length is chosen automatically;
- extreme values downweighted between 1.5 and 2.5 standard deviations,
  measured over rolling five-year spans, with the forecasts included;
- no shrinkage of the seasonal factors and no X-11 Easter estimation;
- no mode: see [Choose a decomposition mode](#choose-a-decomposition-mode).

Each `with_*` method changes one choice:

| Method | Choice |
| --- | --- |
| [`with_mode`](crate::x11::Options::with_mode) | The decomposition mode ([`x11::Mode`]) |
| [`with_seasonal_filter`](crate::x11::Options::with_seasonal_filter) | One [`x11::SeasonalFilter`] for every month or quarter: 3×1, 3×3, 3×5, 3×9, 3×15, stable, the original X-11 sequence, or MSR |
| [`with_seasonal_filters`](crate::x11::Options::with_seasonal_filters) | A filter per calendar month or quarter ([`x11::SeasonalFilters`]) |
| [`with_short_series_filters`](crate::x11::Options::with_short_series_filters) | Stable factors, or the requested filter, for series under five years ([`x11::ShortSeriesFilters`]) |
| [`with_trend_filter`](crate::x11::Options::with_trend_filter) | A fixed Henderson length, an odd number from 3 to 101 ([`x11::TrendFilter`], [`x11::HendersonLength`]) |
| [`with_seven_term_endpoints`](crate::x11::Options::with_seven_term_endpoints) | End weights of a seven-term Henderson filter ([`x11::SevenTermEndpoints`]) |
| [`with_sigma_limits`](crate::x11::Options::with_sigma_limits) | The extreme-value limits ([`x11::SigmaLimits`]) |
| [`with_extreme_scale`](crate::x11::Options::with_extreme_scale), [`with_extreme_estimator`](crate::x11::Options::with_extreme_estimator), [`with_extreme_estimation_span`](crate::x11::Options::with_extreme_estimation_span) | How the scale for extreme values is measured |
| [`with_seasonal_shrinkage`](crate::x11::Options::with_seasonal_shrinkage) | Global or local shrinkage of the seasonal factors ([`x11::SeasonalShrinkage`]) |
| [`with_decomposition`](crate::x11::Options::with_decomposition) | Trend and irregular only, without seasonal adjustment ([`x11::Decomposition`]) |
| [`with_easter_estimation`](crate::x11::Options::with_easter_estimation) | X-11's own Easter estimate; see [Limits](#limits) |
| [`with_holiday_adjustment`](crate::x11::Options::with_holiday_adjustment), [`with_final_outliers`](crate::x11::Options::with_final_outliers), [`with_temporary_change_allocation`](crate::x11::Options::with_temporary_change_allocation) | Where holiday effects and outliers are restored; see [Place outliers and holidays in the components](#place-outliers-and-holidays-in-the-components) |

Pass the options to [`Spec::x11`] or [`Spec::x11_regarima`]. A SEATS request
takes none.

```rust
# fn synthetic(years: usize) -> Vec<f64> {
#     let mut season = [0.90, 0.94, 1.00, 1.03, 1.06, 1.09, 1.08, 1.05, 1.01, 0.98, 0.93, 0.93];
#     let mut state: u32 = 1;
#     let mut noise = move || {
#         state = state.wrapping_mul(1_103_515_245).wrapping_add(12_345);
#         f64::from(state >> 8) / f64::from(1u32 << 24) - 0.5
#     };
#     let mut level = 100.0;
#     (0..12 * years)
#         .map(|i| {
#             level += 0.4 + noise();
#             season[i % 12] += 0.01 * noise();
#             season[i % 12] * level * (1.0 + 0.02 * noise())
#         })
#         .collect()
# }
use x13::{Period, Series, Spec, x11};

let options = x11::Options::new()
    .with_mode(x11::Mode::Additive)
    .with_seasonal_filter(x11::SeasonalFilter::S3x9)
    .with_trend_filter(x11::TrendFilter::Henderson(x11::HendersonLength::new(23)?))
    .with_sigma_limits(x11::SigmaLimits::new(1.8, 2.8)?);
let spec = Spec::x11(options);
let adjustment = x13::adjust(Series::new(Period::monthly(2012, 1)?, &synthetic(8)), &spec)?;

let x11 = adjustment.diagnostics().x11().expect("an X-11 adjustment");
assert_eq!(x11.final_henderson_terms(), 23);
assert!(x11.msr_selection().is_none()); // a fixed filter skips the MSR choice
# Ok::<(), Box<dyn std::error::Error>>(())
```

# Add regARIMA preprocessing

A regARIMA model improves X-11 in three ways. Its forecasts extend the series,
so the filters near the end are closer to symmetric. It estimates calendar
effects, outliers and supplied regressors, and removes them before filtering.
It estimates missing values.

The model's forecasts, calendar effects and outliers stay available on the
result. This example fits the airline model, with trading-day and Easter
effects, to the logarithm of a series with a spike, and searches for outliers
with the default settings:

```rust
# fn synthetic(years: usize) -> Vec<f64> {
#     let mut season = [0.90, 0.94, 1.00, 1.03, 1.06, 1.09, 1.08, 1.05, 1.01, 0.98, 0.93, 0.93];
#     let mut state: u32 = 1;
#     let mut noise = move || {
#         state = state.wrapping_mul(1_103_515_245).wrapping_add(12_345);
#         f64::from(state >> 8) / f64::from(1u32 << 24) - 0.5
#     };
#     let mut level = 100.0;
#     (0..12 * years)
#         .map(|i| {
#             level += 0.4 + noise();
#             season[i % 12] += 0.01 * noise();
#             season[i % 12] * level * (1.0 + 0.02 * noise())
#         })
#         .collect()
# }
use x13::regarima::{
    CalendarBasis, CalendarEffectScale, CalendarSpec, Easter, FlowTradingDay, OutlierSpec,
    OutlierType, TradingDayContrast,
};
use x13::{ArimaModel, Period, RegArimaSpec, Series, Spec, Transform, x11};

let start = Period::monthly(2012, 1)?;
let mut values = synthetic(8);
values[50] *= 1.3; // a one-off spike in March 2016

let calendar = CalendarSpec::new()
    .with_basis(CalendarBasis::FlowTradingDay(FlowTradingDay::new(
        TradingDayContrast::SixCoefficient,
    )))
    .with_easter(Easter::new(8)?);
let preprocessing = RegArimaSpec::new(ArimaModel::airline())
    .with_transform(Transform::Log)
    .with_calendar(calendar)
    .with_outliers(OutlierSpec::new());
let spec = Spec::x11_regarima(preprocessing, x11::Options::new());
let adjustment = x13::adjust(Series::new(start, &values), &spec)?;

let spike = start.shift(50)?;
let outlier = adjustment.outliers().iter().find(|outlier| outlier.period() == spike);
assert_eq!(outlier.map(|outlier| outlier.kind()), Some(OutlierType::Additive));

// Log preprocessing gives calendar effects as factors.
let calendar = adjustment.calendar_effects().expect("calendar effects were requested");
assert_eq!(calendar.scale(), CalendarEffectScale::Factor);
assert_eq!(calendar.combined().len(), values.len());
# Ok::<(), Box<dyn std::error::Error>>(())
```

# Place outliers and holidays in the components

By default the fitted effects land where X-13ARIMA-SEATS puts them:

- **Calendar effects** are removed from the seasonally adjusted series.
  [`x11::HolidayAdjustment::Retain`] keeps the holiday part (Easter, Labor Day,
  Thanksgiving) in the adjusted series and the irregular.
- **Outliers** stay in the seasonally adjusted series. Level shifts go to the
  trend; additive outliers and temporary changes go to the irregular.
- [`x11::FinalOutliers::Remove`] takes the chosen outlier types out of the
  adjusted series (and level shifts out of the trend). The irregular keeps
  them.
- [`x11::TemporaryChangeAllocation::Trend`] moves temporary changes from the
  irregular to the trend, unless final outlier removal already takes them.

These settings change only where effects are restored. They do not change the
fit, the outlier search or the effects reported on the result. Set them with
[`x11::Options::with_holiday_adjustment`],
[`x11::Options::with_final_outliers`] and
[`x11::Options::with_temporary_change_allocation`]. The last two act on the
outliers of a regARIMA model, so [`Spec::x11`] ignores them.

```rust
# fn synthetic(years: usize) -> Vec<f64> {
#     let mut season = [0.90, 0.94, 1.00, 1.03, 1.06, 1.09, 1.08, 1.05, 1.01, 0.98, 0.93, 0.93];
#     let mut state: u32 = 1;
#     let mut noise = move || {
#         state = state.wrapping_mul(1_103_515_245).wrapping_add(12_345);
#         f64::from(state >> 8) / f64::from(1u32 << 24) - 0.5
#     };
#     let mut level = 100.0;
#     (0..12 * years)
#         .map(|i| {
#             level += 0.4 + noise();
#             season[i % 12] += 0.01 * noise();
#             season[i % 12] * level * (1.0 + 0.02 * noise())
#         })
#         .collect()
# }
use x13::regarima::{OutlierSpec, OutlierTypes};
use x13::{ArimaModel, Period, RegArimaSpec, Series, Spec, Transform, x11};

let start = Period::monthly(2012, 1)?;
let mut values = synthetic(8);
values[50] *= 1.3;

let preprocessing = RegArimaSpec::new(ArimaModel::airline())
    .with_transform(Transform::Log)
    .with_outliers(OutlierSpec::new());
let retained = Spec::x11_regarima(preprocessing.clone(), x11::Options::new());
let removed = Spec::x11_regarima(
    preprocessing,
    x11::Options::new().with_final_outliers(x11::FinalOutliers::Remove(OutlierTypes::ADDITIVE)),
);

let retained = x13::adjust(Series::new(start, &values), &retained)?;
let removed = x13::adjust(Series::new(start, &values), &removed)?;
let (retained_adjusted, removed_adjusted) = (
    retained.seasonally_adjusted().values(),
    removed.seasonally_adjusted().values(),
);
assert!(retained_adjusted[50] > 1.2 * removed_adjusted[50]);
assert_eq!(retained.irregular().values()[50], removed.irregular().values()[50]);
# Ok::<(), Box<dyn std::error::Error>>(())
```

# Read the components

[`Adjustment::seasonal`], [`Adjustment::seasonally_adjusted`],
[`Adjustment::trend_cycle`] and [`Adjustment::irregular`] cover the observed
span, one value per input value (X-13ARIMA-SEATS tables D10, D11, D12 and
D13). `seasonal` and `trend_cycle` return an `Option` because SEATS can omit
them; X-11 always returns `Some`. Each component is a [`Series`] that starts at
[`Adjustment::start`], the input's first period; [`Series::values`] is the
plain slice.

Additive X-11 gives the seasonal and irregular in series units.
Multiplicative, log-additive and pseudo-additive X-11 give them as factors
around one. The adjusted series and trend are always in series units.

# Read the X-11 diagnostics

[`Diagnostics::x11`] returns the [`x11::Diagnostics`] of an X-11 adjustment:

- [`mode`](crate::x11::Diagnostics::mode), the mode actually used;
- [`final_henderson_terms`](crate::x11::Diagnostics::final_henderson_terms),
  the length of the final trend filter;
- [`msr_selection`](crate::x11::Diagnostics::msr_selection), the filter the MSR
  chose, or `None` when no month or quarter asked for MSR;
- [`calendar_sigma_selection`](crate::x11::Diagnostics::calendar_sigma_selection),
  the outcome of an automatic extreme-value scale;
- [`seasonality`](crate::x11::Diagnostics::seasonality), the nine seasonality
  tests: stable, moving and Kruskal–Wallis tests, the combined test, and
  residual seasonality in the adjusted series;
- [`quality`](crate::x11::Diagnostics::quality), the M1 to M11 and Q quality
  measures;
- [`spectral`](crate::x11::Diagnostics::spectral), spectral peaks in the
  original, adjusted and irregular series of a monthly adjustment.

Probabilities are percentages. Each test, each spectrum, and the quality
measures as a whole, is a `Result`: the value, or an [`Unavailable`] that says
why there is none. An unavailable diagnostic does not invalidate the
components. The regARIMA model's residual spectrum is on
[`ModelResult::residual_spectral`].

Read [`Adjustment::warnings`] on every result. Warnings report spectral peaks,
filters replaced on short series, rejected forecasts and similar events. The
crate does not report every warning X-13ARIMA-SEATS prints.

# Limits

These combinations return an error rather than an adjustment:
[`Error::InvalidSpec`] unless another is named.

- **X-11 Easter** ([`x11::Options::with_easter_estimation`]) works on monthly
  series in multiplicative or pseudo-additive mode. It cannot be combined
  with a fitted Easter regressor or automatic transformation, and under
  pseudo-additive X-11 it needs [`x11::HolidayAdjustment::Retain`]. Combined
  with calendar selection it is unsupported ([`Error::Unsupported`]). Without
  calendar regressors in the model, the estimated effect stays in the
  seasonally adjusted series.
- **Pseudo-additive** X-11 takes no regression effects other than the
  regressors that stand in for missing values. A series with gaps needs the
  log transform, and rejects a constant and the removal of additive outliers,
  because each of those regressors counts as an additive outlier. With no
  outliers in the model, final outlier removal has nothing to remove. Without
  gaps it needs a fixed model with a constant, and then has no effect.
- **Trend-only** decomposition rejects explicit seasonal filters and
  log-additive mode.
- **Local shrinkage** needs at least five monthly forecasts or one quarterly
  forecast that X-11 uses, so it does not work with direct X-11. Too few
  return [`Error::Numerical`]; the remedy is a longer forecast
  horizon, not another model.

X-11 regression on the irregular, sliding spans, revision history and the
X-13ARIMA-SEATS report output are not implemented.
